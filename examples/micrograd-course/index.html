The hundred lines that learn

What micrograd is, and what happens in the instant you write a + b.

What this thing is

micrograd is a miniature version of the machinery inside PyTorch — the software that trains almost every A stack of simple arithmetic operations whose numbers get nudged, over and over, until the stack produces useful answers. It exists to answer one question, millions of times a second: which dial should I turn, and which way, to make this answer less wrong?

A trail of breadcrumbs

In ordinary Python, 4 + 2 gives you 6, and the 4 and the 2 are gone. The answer has no memory of its parents.

micrograd refuses to forget. Every result keeps a pointer back to the numbers that made it — breadcrumbs dropped on the way out, so the trail can be walked backwards later.

Code micrograd/engine.py, lines 13-22 
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward

        return out
In plain English
  1. This runs every time you write a + b and a is one of micrograd's numbers.
  2. If you added a plain 2, quietly wrap it first, so everything downstream can assume it is dealing with the same kind of thing.
  3. Make the answer — and notice it stores three things, not one: the sum, who its two parents were, and the label '+'.
  4. Now write the note-to-self: when someone eventually tells me how much I mattered, here is how I pass that message back to my parents.
  5. For addition the answer is beautifully lazy. Nudge the sum up by one and each input contributed exactly one, so both parents get the message unchanged.
  6. Staple that note to the answer and hand it back.
💡
A function that outlives the one that made it

A function defined inside another function, still alive after the outer one has finished, is called a A function that remembers the variables that surrounded it when it was created, even after that surrounding code has finished. Here, _backward still remembers self, other and out long after __add__ returned.. It is what lets a result carry its own instructions for undoing itself.

Step through what Python builds when you write one short line.

  1. Python evaluates a * b first, making a new number that remembers a and b.
  2. That temporary number is then added to c, making a third number.
  3. d holds 18.0 and the entire family tree hangs beneath it.

That family tree has a name engineers use constantly: a Directed acyclic graph: a set of things joined by one-way arrows, with no way to loop back to where you started. A family tree is one; a circular argument is not.. Saying "micrograd builds a DAG of scalar operations" to an assistant gets you a far more precise answer than "it does the maths thing".

Decision

Scalars, not tensors — every number is its own object

README.md — "The DAG only operates over scalar values… potentially useful for educational purposes"

What was chosen

One Value per number; a neuron becomes visible adds and multiplies.

What was rejected

Tensors — whole grids of numbers moved at once, the way every production framework works.

What it costs

Speed, catastrophically — an object and two closures per operation.

Revisit it when

Never — the README says educational. When speed matters, the answer is PyTorch.

The wrapping trick has a mirror image: it also works when the plain number comes first.

How it actually works

Write 2 * x and Python asks the number 2 to multiply first — and 2 has never heard of Value. Python then tries the reflected version, __rmul__, on x, and engine.py defines the full set: __radd__, __rsub__, __rmul__, __rtruediv__. Each just flips the operands and reuses the normal path, so both orderings build the same graph.

A performance-minded engineer

An object allocation and two closures for every single addition? This is the least efficient arithmetic ever written. Why would anyone study code that no one would ever ship?

Answer it in your head first. Then check.

How you would answer

Because the inefficiency is the pedagogy. PyTorch does conceptually identical bookkeeping — a graph of operations, each remembering its inputs and how to push gradients back — but buried in C++ and batched over tensors, where no one can watch it happen. micrograd unrolls the same machine into 94 readable lines. You study it precisely because it makes the invisible thing visible; you ship the other one.

What will not survive: "it could be optimised later". The follow-up is then why hasn't anyone? — the honest position is that its slowness is a deliberate, stated trade for legibility, not a gap waiting for a patch.

One neuron, in full

A neuron sounds mystical. It is four lines of arithmetic and one decision.

Code micrograd/nn.py, lines 15-22 
    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
        return act.relu() if self.nonlin else act
In plain English
  1. Set up a neuron that expects a certain number of inputs.
  2. Give it one A dial controlling how much one input matters to this neuron. Training is nothing more than turning these dials a little at a time. per input, each starting somewhere random between -1 and 1. Random, because identical starting dials would make every neuron learn the identical thing.
  3. Add a A constant the neuron adds no matter what the inputs are. It shifts the threshold, letting the neuron fire more or less eagerly. starting at zero — its opinion before it has seen anything.
  4. Remember whether this neuron should flatten its output or pass it through raw.
  5. This is what runs when you treat the neuron like a function and write n(x).
  6. Pair each input with its weight, multiply, and total them up — starting the running total at the bias rather than at zero. That detail is why the bias needs no line of its own.
  7. Optionally pass the result through A rule that says: if the number is negative, make it zero; otherwise leave it alone. That single kink is what lets stacked layers learn curved patterns instead of only straight lines.. Without that kink, stacking a hundred layers would still only ever draw a straight line.

Remembers one number, who made it, and how to pass credit back

Weighs each input, totals them with a bias, optionally clips at zero

Runs a row of those on the same input and collects the answers

Feeds the output of one stage into the next, front to back

One call — model.parameters() — reaches every trainable number in the network, because each level asks the level below.

How it actually works

The base class Module defines parameters() returning an empty list, and zero_grad() that loops over whatever parameters() yields. Neuron overrides it with its weights plus bias; Layer concatenates its neurons' lists; MLP concatenates its layers'. Nothing keeps a registry — the list is rebuilt by recursion every call, which is why nothing can ever be stale.

Decision

Copy PyTorch’s API shape instead of inventing one

README.md — "a small neural networks library… with a PyTorch-like API"

What was chosen

The idioms learners will meet next: model(x), parameters(), zero_grad(), backward().

What was rejected

A cleaner bespoke interface that might avoid PyTorch’s sharp edges.

What it costs

It inherits the footguns too — chief among them that forgetting zero_grad() fails silently, exactly as it does in the real thing.

Revisit it when

Never for this library: transferring to PyTorch is the goal, so matching its shape is the feature.

Someone who values reproducibility

Weights start at random.uniform(-1,1), so every run gives different results. Zeros would be reproducible — why is randomness the default?

Answer it in your head first. Then check.

How you would answer

Start every weight at the same value and every neuron in a layer computes the same output, receives the same gradient, and takes the same update — they are clones at birth and clones forever, so a hundred-neuron layer learns exactly one thing. Randomness is not decoration; it is what breaks the symmetry so neurons can specialise. Reproducibility is recovered the standard way: seed the generator, keep the randomness.

What will not survive: "random just works better in practice". The follow-up is why? — and if you cannot say "identical neurons get identical gradients", you have a superstition, not an answer.

The forward pass

You hand the network two numbers. Follow them all the way to an answer.

A rumour going up a building

Each floor of an office hears the rumour from the floor below, adds its own spin, and passes it up. Nobody on the third floor ever speaks to the first — each One row of neurons, all reading the same input and each producing a single number. Stacking layers is what makes a network deep. only knows what the one below it said.

That is the One trip through the network, inputs to output, producing a prediction. The return trip — working out who was to blame for the error — is the backward pass., and it is three lines long.

Nothing has been learned yet

Read the last message again: the gradient is still zero. The forward pass produces an answer and builds a graph, and that is all it does. Learning has not started.

The graph is not a permanent structure — a fresh one is built on every single call, as a side effect of the arithmetic.

How it actually works

Nothing in nn.py stores connections between calls. Each model(x) runs the multiplies and adds again, and each operation mints new Value objects with fresh parent links — the graph exists because the arithmetic just happened, and is garbage-collected afterwards. That is why the training loop may freely change p.data between calls: next call, a new graph is built around the nudged numbers.

An API designer, reading Layer’s last line

Returning a bare Value when there is one neuron but a list when there are two is an inconsistency that will bite someone. Pick one shape and keep it.

Answer it in your head first. Then check.

How you would answer

It is a deliberate convenience aimed at the most common case: the final layer of a classifier has one neuron, and unwrapping there means every caller writes score instead of score[0]. The criticism is still fair — in the middle of a network the changing shape genuinely surprises people, and PyTorch chose the opposite trade: always a tensor, always the same shape. Defensible is not the same as free; this one purchases ergonomics at the price of a surprise.

What will not survive: "nobody will notice". The follow-up is chapter three’s own quiz — the shape difference is noticeable enough that this course tests for it.

Chapter 04

Backpropagation

The return journey that assigns blame — and the only reason any of this learns.

The incident review

A parcel arrives three days late. The investigation does not start at the warehouse; it starts at the doorstep and works backwards. The courier was late because the depot was late, because the sorting hub was late.

Each stage learns how much of the delay was its own. That backwards walk is Walking the graph from the answer back to the inputs, working out how much each number contributed to the error. Say it by name to an assistant and you will get precise help., and the number each node ends up holding is its The answer to one question: if I nudge this number up slightly, does the final error go up or down, and by how much? Positive means nudging up makes things worse..

In plain English
  1. The comment names the rule from calculus this implements. You do not need the calculus; you need to know the walk exists.
  2. Seed it: this node's effect on itself is exactly one. Nudge the error up by one and the error goes up by one.
  3. Now walk the list of nodes backwards. The order was worked out a few lines earlier, and it is the whole trick.
  4. Fire each node's note-to-self, the one that was stapled on when it was created. Because of the ordering, every node has already collected all of its incoming credit before it passes any on.
💡
You have met this ordering before

Listing every node so that parents always come before children is a Arranging items so that everything a step depends on comes before it. The same expression as chapter one, running in reverse.

  1. The final node is seeded with a gradient of 1.
  2. Addition passes its gradient to both parents unchanged.
  3. Multiplication scales each parent by what the other held.
  4. The inputs end up holding how much each of them mattered.

One character that is easy to miss

Every note-to-self in engine.py adds to the gradient with +=, never =. It looks like a style choice. It is not.

➕

Why it adds

A number used in two places earns credit from both. Assigning would let the second contribution quietly erase the first.

🧹

Why wiping matters

Because gradients accumulate, they have to be cleared before every training step, or this round's blame lands on top of last round's.

🔁

Same trap in PyTorch

Real training loops call zero_grad for exactly this reason. Same trap, same fix, four orders of magnitude more code.

The ordering guarantees each note-to-self fires exactly once, only after all of its incoming credit has arrived.

Where it gets subtle

The subtlety is a number used twice. In a + a, both parents of the sum are the same object, so its note adds to a.grad twice — which is the correct calculus, and only works because the notes accumulate with += onto a node that fires after all paths have reported. Replace += with = and the second path silently erases the first. The fieldwork below lets you catch this with your own eyes.

Decision

What was chosen

An assert that refuses a Value exponent, with the reason written into the error message itself.

What was rejected

General x ** y where both vary — which would drag logarithms into the gradient rule for a case the library never needs.

What it costs

Division works only because it is rewritten as x * other**-1; anything fancier with exponents is simply out of bounds.

A newcomer reading backward() closely

Why does the walk start with self.grad = 1? That looks like an arbitrary magic number smuggled into the maths.

Answer it in your head first. Then check.

How you would answer

It is the one gradient you get for free: the question every gradient answers is "if this number moves, how much does the final number move?" — and the final number moves one-for-one with itself. Every other gradient in the graph is manufactured from that seed by the chain rule, each note multiplying or passing it backwards. Change the seed to 2 and every gradient in the network doubles, which is exactly why 1 is the only honest start.

What will not survive: "it is just a convention". The follow-up — what would happen with 0? — has a concrete answer (every gradient becomes 0 and nothing learns), which proves the value is doing real work.

Chapter 05

When it breaks

The failures that never raise an error, and how to smell them out anyway.

Every bug here is silent

A website that breaks throws a red The list of function calls that led to a crash, printed newest first. It tells you where the program was standing when it gave up. at you. A training loop that breaks returns a number.

A perfectly reasonable-looking, completely wrong number. This is the most useful thing to internalise about machine learning code: the absence of an error means nothing.

The error falls, then explodes

Blame accumulating across steps — a missing wipe, or a step size too large

The error refuses to move

Every gradient is zero. Often an entire layer is stuck in the flat negative half of ReLU

It dies on a big batch

A function that calls itself to handle a smaller piece of the same problem. Each call waits for the one inside it, and every language caps how deep that nesting may go.: the ordering step calls itself once per node, and Python gives up around a thousand deep

The four lines that prevent most of it

The whole defence lives on the shared base class, so every neuron, layer and network inherits it.

Code micrograd/nn.py, lines 4-8 
class Module:

    def zero_grad(self):
        for p in self.parameters():
            p.grad = 0
In plain English
  1. A Behaviour written once and shared by several other classes, instead of copied into each. Neuron, Layer and MLP all build on this one. that the three network pieces share, so these lines are written once rather than three times.
  2. Wipe every gradient inside whatever this object contains.
  3. Ask for the full list of dials — the same recursive walk from chapter two, so calling this on the network reaches every weight in it.
  4. Set each accumulated blame back to zero. Miss this and the next backward pass adds to numbers that are already stale.

This training loop runs without complaint and never improves. One line is responsible.

The correct loop, one move at a time

Four moves in a fixed order. Get the order wrong and nothing complains.

Ask the network what it thinks. Numbers flow front to back and a graph gets built as a side effect. No learning happens here at all.

Measure how wrong it was. The error is itself one of micrograd's numbers, sitting at the top of the graph — which is precisely why you can start the backward walk from it.

Wipe first, then assign blame. Clear the gradients, then walk backwards. Skip the wipe and every step inherits the last one's numbers.

Turn every dial a little. Each parameter moves against its gradient. Only the stored number changes — the graph itself is rebuilt from scratch next time round.

The recursion crash is a property of Python’s call stack, not of micrograd’s logic — the maths would be fine one node deeper.

How it actually works

build_topo calls itself once for every node it has not yet visited, and each unfinished call occupies a stack frame while it waits. A long chain of operations means a long chain of waiting frames, and Python refuses somewhere near a thousand. The standard cure is mechanical — an explicit stack in a loop instead of the call stack — and the reason micrograd does not use it is the same reason it does everything else: the recursive version reads like the definition of the ordering it computes.
